# v0.4 candidate rules as dials — phase A: engine and bots (contract)

The independent design review (an internal note, not published; sections 3 and 6) proposes rule changes. This
phase builds them as `[game]` dials that are **off by default** and measures them with the scripted
bots only. No model plays these rules yet: prompts, transcript, live watch, report and the viewer
are phase B, and only happen if the bot results justify it.

Read first: the design review (sections 3, 6), `RULES.md`, `docs/SPEC.md` sections 4-6, 8,
11, 12, then `inside_job/engine.py`, `bots.py`, `schemas.py`, `log.py`, `solver.py`, `clues.py`,
`config.py`.

## Dials (`[game]`, all validated in `config.py`)

| Key | Default | Meaning |
|---|---|---|
| `mole_score_target` | `0` | `0` = off (today's `sabotage_target` rule). `> 0`: the moles' score is blown jobs + crew members voted out; the moles win when it reaches this number. `sabotage_target` is then not used. |
| `vote_nobody` | `false` | The vote offers `nobody`. A player is voted out only with a strict majority of the alive voters (more than half); otherwise nobody goes and there is no tie-break. |
| `forced_vote_after` | `2` | Only with `vote_nobody`: after this many votes in a row with nobody out, the next vote has no `nobody` option and uses today's rule (plurality, leader tie-break, then random). `0` = never forced. |
| `team_approval` | `false` | Pre-job debate with approve / reject (below). |
| `whisper_pairing` | `"chosen"` | `"random"`: the engine draws the pairs. |
| `clue_turn` | `true` | `false`: clues are dealt but the clue-phase call is not made. Needs `whispers = false` or `whisper_pairing = "random"`. |
| `endings` | `"classic"` | `"stakes"`: no Cut; endings below. |
| `unique_clues` | `false` | In one round no two players are dealt the same clue (same kind, players and k), unless no other clue exists. |

`GameConfig.v04_dials()` returns the names of the dials that are away from their default.

**Bot-only guard.** `Game.__init__` raises a clear error when `v04_dials()` is not empty and the
client needs prompts (`needs_prompt` is true), naming the dials: the prompts for these rules are not
written. Tests of the new rules therefore use a client with `needs_prompt = False` (the bots, or a
`Script` / `MockLLM` variant you add to `tests/helpers.py`).

## Rules when a dial is on

### Mole score (`mole_score_target > 0`)
- `crew_ejected` counts crew members voted out. `mole_score = blown_jobs + crew_ejected`.
- End checks, in order. After a job: mole score reached → moles win, reason `mole_score`; clean
  target reached → crew, `jobs_clean`. After a vote: mole score reached → moles, `mole_score`; no
  mole alive → crew, `moles_out`; two or fewer alive → moles, `final_two`; clock as today, except
  that `max_rounds = 0` now means **no clock** (jobs end the game by themselves).
- `round_start` and `game_end` carry `crew_ejected` and `mole_score`.

### Nobody vote (`vote_nobody`)
- Vote enum: the other alive players plus `nobody` (unless this vote is forced).
- `vote_result` keeps its shape; with nobody out `eliminated` and `role` are `null`, `tied` is
  empty, `tiebreak` is `null`. It gains `forced: bool` and `needed` (votes needed to eject).
- Everything that reads `vote_result` on the bot path must accept `eliminated = null`
  (`bots._State`, `solver.inputs_from_view`, `bots.game_summary`, engine `vote_record`).

### Team approval (`team_approval`)
Round order becomes: clues → whispers → pick → **debate** → (if rejected: next leader's forced
pick) → job → `discussion_passes` passes of discussion → vote → recap.
- New turn phase `debate` (log phase `debate`): one statement each from every alive player in
  discussion order (left of the leader first, leader last). Action: `accuse`, `challenges`,
  `clue_cards`, `approve` (boolean), `suspicion`. No `job_claim`. It is a statement phase and a
  suspicion phase, gets a statement id, clue-card `checks`, and can be challenged later in the
  round. `approve` is public as it is spoken.
- After the last speaker: public event `team_vote` with `leader`, `team`, `approvals`
  (`{name: bool}` in speaking order), `approve`, `reject`, `approved`. The team goes ahead only
  with a strict majority of approvals among alive players.
- Rejected: the lead passes to the next alive seat (and stays there: next round's leader is the
  seat after it). That leader makes a normal `pick` turn; the `job_pick` event has
  `forced: true`; there is no second debate. (The first `job_pick` has `forced: false`.)
- Fallback for a failed `debate` turn: approve, accuse nobody, no cards.

### Random whispers (`whisper_pairing = "random"`)
- Pairs come from a new stream `random.Random(f"{seed}:whispers")`: shuffle the alive players in
  seat order, pair them off, keep the first `min(whisper_pairs_max, alive // 2)` pairs; the first
  drawn of a pair speaks first. No `whisper_with` in the clue turn, no `whisper_requests` event;
  `whisper_pairs` gains `pairing: "random"`.
- `whisper_exchanges` is unchanged (the v0.4 config sets it to 1).
- The deal stream is untouched: the same seed gives the same moles, first leader, codenames and
  first-round clues whatever the dials say.

### No clue turn (`clue_turn = false`)
- `clue_deal` and `clue` events are written as today; no calls are made in the clue phase.

### Endings (`endings = "stakes"`)
- No Cut, no crew-versus-crew split / steal.
- **Moles win:** two moles alive → today's split / steal finale between them
  (`finale_exchanges` as configured); one alive → that mole takes the pot.
- **Crew win by `moles_out`:** the pot is shared equally among the alive crew (`pot // k` each).
- **Crew win by `jobs_clean`** (a mole is always still hidden then): **Final Accusation.** Every
  alive player, moles included, names one other alive player at the same time. New turn phase
  `final_accuse` (log phase `finale`): a short public line plus `accuse`. Public event
  `final_accusation`: `votes`, `tally`, `tied`, `tiebreak` (`random` from the play stream, or
  `null`), `accused`, `role`, `hit`, `payouts`. Hit (the accused is a mole): the alive crew share
  the pot equally. Miss: the alive moles share it equally. `game_end.winner` stays `crew` either
  way.
- Fallback for a failed `final_accuse` turn: a random other alive player.

### Unique clues (`unique_clues`)
- `generate_clue` takes the clues already dealt this round and avoids them when another candidate
  exists.

## Bots

Additive changes to `Bot` / `BotLLM` / the `bots` command:

- **Vote with `nobody`:** crew vote their top suspect when their belief in it is at least
  `eject_threshold` (default `0.5`), else `nobody`; a random-acting crew bot picks uniformly from
  the enum. Moles vote for the table's top suspect who is not a partner (they want an ejection).
  A forced vote is played as today.
- **Debate:** crew approve when their probability that the team holds at least one mole is below
  `approve_threshold` (default `0.45`), computed over worlds (not from marginals); cards and
  accusation as in discussion. Moles: `mole_approve = "blend"` (default) approve exactly when a
  logician holding only the table's public evidence would; `"team"` approve exactly when a mole
  is on the team.
- **Final Accusation:** crew name their top suspect; moles name the table's top suspect who is
  not a partner.
- **New mole type `hold1`:** `smart`, but never sabotages in round 1 (what the real moles did in
  pilot 1: 0 of 8).
- Command options: `--eject-threshold`, `--approve-threshold`, `--mole-approve {blend,team}`,
  `--moles` gains `hold1`. These three thresholds can also be swept: `--sweep` accepts
  `bot.eject_threshold=...`, `bot.approve_threshold=...` alongside `[game]` keys.
- `game_summary` / `cell_stats` gain: crew ejected, mole score, votes held / with nobody out /
  forced, team votes / rejections, Final Accusation held / hit, zero-blown-job games, games over
  by round 2. The printed table shows the new columns **only when a v0.4 dial is on in some
  cell**; otherwise its text is what it is today. `REASONS` gains `mole_score`.

## Tests (`tests/test_v04.py`)

1. Defaults: fixture equality for mock games and for a small bot cell (see above).
2. Config: each dial's validation; `clue_turn = false` with chosen whispers is rejected; the
   bot-only guard fires with a prompt-needing client and not with the bots.
3. Mole score: a scripted game that ends on a wrongly ejected crew member (`mole_score`), one
   that ends on a blown job, and the counters in `round_start` / `game_end`.
4. Nobody vote: no majority → nobody out; exact majority boundary for even and odd tables;
   forced vote after `forced_vote_after` empty votes and the streak resetting after an ejection.
5. Team approval: approved path, rejected path (leader moves, forced pick, no second debate,
   next round's leader), tie = rejected, `debate` statement ids and challenges, fallback.
6. Random whispers: pairs are a function of the seed only, never repeat a player, respect the
   cap; no `whisper_requests`; the deal (moles, first leader, round-1 clues) equals the
   chosen-pairs game of the same seed.
7. No clue turn: no clue-phase turns; clues still reach the player's view.
8. Endings: each branch (two moles win, one mole wins, `moles_out` share, Final Accusation hit
   and miss, tie-break), payouts sum to at most the pot, no `cut_result` ever.
9. Privacy (follow `tests/test_privacy.py`): in a full-dials game the table view and each
   player's view hold no confessional, suspicion, check, role or job choice they should not;
   `approve` and the Final Accusation votes are public, the reasons private as for votes today.
10. Unique clues: 200 seeded rounds with no duplicate in a round.
11. Bots: 300 games with the full v0.4 config at skill 0.7 finish with zero fallbacks, for each
    mole type.
12. The whole suite passes: `python3.11 -m unittest discover -s tests` (if `tests/test_viewer.py`
    fails because the other agent is mid-edit, say so and list the failures; do not touch it).

## Build notes (phase A, 2026-11-10)

What was built, and every place where this build reads the contract one way or departs from it.

**Defaults fixture and golden check.**
- Before any code changed, `tests/fixtures/v04_defaults/make_fixture.py` was run on the untouched
  code. It pins mock games (`pilot.toml` seeds 1-3, `pilot2.toml` seeds 1-2), the event streams
  of bot games (`pilot.toml`, skill 0.7, decoy cards, moles smart / always / never, seeds 1-12)
  and the per-game rows and printed row for 30 games of each. `tests/test_v04.py` (`Defaults`)
  replays them. The script only makes sense on pre-v0.4 code; do not re-run it to "fix" a
  failing comparison.
- The golden folder was checked with a script outside the project that re-runs the contract's
  reference commands (`run --mock` into a temporary folder; `bots` with the four golden argument
  lists) and compares event by event with `ts`, `game_id`, `wall_s`, `latency_s` dropped at every
  depth and the new `game_start.config.game` keys set aside, and the bot tables with only the
  timing figures (`g/s`, wall time) removed. It passed on a pristine copy of the old code (to
  prove the checker) and on the new code.

**Phase constants.** `schemas.PHASES`, `SUSPICION_PHASES` and `STATEMENT_PHASES` are unchanged:
`tests/test_v03.py` pins `SUSPICION_PHASES` to the four v0.3 phases and existing tests may not be
edited. The new phases live in `schemas.V04_PHASES`, `V04_STATEMENT_PHASES` (`debate`,
`final_accuse`) and `V04_SUSPICION_PHASES` (`debate`). `log.PUBLIC_TURN_PHASES` and
`PUBLIC_ACTION_KEYS` gained `debate` (`accuse`, `challenges`, `clue_cards`, `approve`) and
`final_accuse` (`accuse`); nothing in a default log has those phases.

**Config.**
- `forced_vote_after` away from 2 without `vote_nobody` is rejected ("only applies with
  vote_nobody"), rather than silently ignored.
- With `vote_nobody` on, a player named `nobody` (any case) is rejected; without it the name is
  allowed as before.
- The bot-only guard raises `ValueError` from `Game.__init__` naming the dials. `run --mock
  --config config/v04_bots.toml` therefore stops with that error (a traceback; `__main__.py` was
  not changed for it).
- `config/v04_bots.toml`'s first line says "rules v0.3 plus every v0.4 candidate dial":
  `test_v03` requires "v0.3" in the first line of every config, and `RULES_VERSION` stays "0.3".

**Engine.**
- Nobody vote: `tally` lists the players in seat order and then `nobody` (when anyone voted it),
  so it sums to the number of voters. A forced vote's `vote_result` has `forced: true` and
  `needed: null` (plurality has no threshold). A failed vote turn falls back to `nobody` when that
  option is offered (no draw from the play stream); in a forced vote it falls back as today.
- Team approval: after a rejection the new leader is the leader for the rest of the round
  (their forced pick, the discussion order, the vote tie-break), not just for the pick. Debate
  turns carry no `pass` field. `job_pick.forced` exists only when `team_approval` is on.
- Mole score: implemented as one ordered check (mole score; clean target; moles out; final two;
  clock unless `max_rounds = 0`) after both the job and the vote. The extra checks cannot fire at
  the other point, so the outcomes are the ones the contract lists.
- Stakes endings: with more than two moles alive (only possible with `num_moles > 2`) the moles
  share the pot equally; the contract covers one and two. Shares are `pot // k`, so a remainder
  (e.g. 1 of 100 among 3) is not paid out. Final Accusation statements get `F-S<n>` ids, as
  finale pitches do. The `final_accusation` event's `tally` is in seat order.
- Unique clues: duplicates are dropped from the candidate list before the closest-to-target
  choice; if that leaves nothing the unrestricted list is used. With `avoid=None` the function is
  the same code path in the same order, so the deal stream draws exactly as before.
- Random whispers: the `{seed}:whispers` stream is created for every game (creating a
  `random.Random` draws nothing from the other streams).

**Bots.**
- Skill noise applies to the new crew decisions as to the old ones: a random-acting crew bot
  votes uniformly over the enum (including `nobody`), names a uniform random player in the Final
  Accusation, and approves on a coin flip in the debate. The debate draws `random_act` twice
  (accusation, then approval), as two decisions.
- Crew approval uses the bot's own worlds (`player_worlds`: its clues, whisper cards, "I am not a
  mole", with today's fallback when no world fits). Mole `blend` approval uses `table_worlds` on
  the public cards, jobs and reveals (with the same fallback), with no self-exclusion.
- The rule "approve when P(a mole on the team) < 0.45" is applied literally, including by a crew
  leader to their own team. With no evidence, a crew bot puts that probability at 0.6 (on the
  team) or 0.8 (off it) for a three-person round-1 team, so round-1 teams are mostly rejected
  and the forced team goes ahead. This is reported, not tuned (see `docs/v04_bot_results.md`).
- Moles always vote for an ejection (the table's top non-partner suspect), while crew often vote
  `nobody`. The vote is public, so that is a tell; the logician bots do not read behaviour and
  never exploit it. The results file says so next to the numbers.
- `--sweep` takes `bot.eject_threshold` and `bot.approve_threshold` (floats) alongside `[game]`
  keys; `--mole-approve` is an option only, as in the contract. The final summary line of `bots`
  names the v0.4 bot options only when they are away from their defaults, so the default text is
  unchanged.
- `game_summary` rows and `cell_stats` always carry the new keys (so `bots --out` files gain keys
  under any config); the printed table gains its columns only when a cell has a v0.4 dial on.

**Measurement choices for the results.** "One dial at a time" treats `team_approval` together
with `discussion_passes = 1` (as in `v04_bots.toml`, where the debate replaces the first
discussion pass), and "full minus team approval" restores `discussion_passes = 2`. The other
groupings are as the contract says.

**Not done here.** `docs/SPEC.md` is not updated (another agent owns it during this phase); the
prompts, transcript, live watch, report and viewer know nothing of the new events (phase B).
